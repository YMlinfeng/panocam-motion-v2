## 3. 准备原始素材

本机默认路径已经写在 `config/pipeline.yaml`：

```yaml
source_roots:
  360x: ../panocam/data/dataset_showcase/360x/hr_samples
  commons: ../panocam/data/panos
```

相对路径以新项目根目录为基准，因此会读取相邻的旧素材目录，但不会读取旧代码和旧 demo。

如果换电脑，不必改代码。可以直接覆盖：

```bash
local/.venv/bin/python scripts/pipeline.py audit \
  --source-root-360x /data/360x/hr_samples \
  --source-root-commons /data/wikimedia
```

渲染时要传入同样的覆盖目录，或把它们永久写回 `config/pipeline.yaml`：

```bash
local/.venv/bin/python scripts/pipeline.py render --workers 2 \
  --source-root-360x /data/360x/hr_samples \
  --source-root-commons /data/wikimedia
```

要增加源视频，在 `config/pipeline.yaml` 的 `sources:` 下增加：

```yaml
- dataset: 360x
  file: your_file.mp4
  manual_decision: pass
  note: 固定机位，人物持续运动，人工检查通过
```

`manual_decision: pass` 不是无条件放行；它仍需通过分辨率、帧率、动态和全局运动阈值。`reject` 则会直接拒绝，适合标记已确认的运动相机或静止内容。

## 4. 第一步：筛选素材

```bash
local/.venv/bin/python scripts/pipeline.py audit
```

它会：

1. 检查文件存在和能否解码；
2. 检查 ≥3840×1920、≥20 fps、≥16 秒；
3. 在整段视频中均匀取最多 5 个完整 15 秒窗口；
4. 对每个窗口计算 `dynamic_score`；
5. 计算 `global_flow_px` 和 `coherent_shift_px`；
6. 联合人工决定给出最终 pass/reject；
7. 写入 `output/SOURCE_AUDIT.json`。

建议检查：

```bash
python3 - <<'PY'
import json
d=json.load(open('output/SOURCE_AUDIT.json'))
print(d['summary'])
for s in d['sources']:
    print(s['final_status'], len(s['usable_windows']), s['file'])
PY
```

### 筛选参数怎么调

| 参数 | 默认 | 调大以后 | 调小以后 |
| --- | ---: | --- | --- |
| `dynamic_score_min` | 0.006 | 更严格，剔除更多弱动态 | 保留更多轻微动态 |
| `global_flow_px_max` | 1.8 | 容许更多全局运动 | 更严格剔除运动机位 |
| `coherent_shift_px_max` | 10 | 容许更大整体位移 | 更严格剔除统一摇移 |
| `max_windows_per_source` | 5 | 检查更全面但更慢 | 更快但覆盖时间段更少 |
| `min_width/min_height` | 3840/1920 | 只留更高分辨率 | 可接受更低清晰度 |
| `min_fps` | 20 | 只留更流畅源 | 允许低帧率源 |

不要仅靠调宽阈值让运动相机通过。对算法不确定的源，应先目视检查，再用 `manual_decision` 明确记录。

## 6. 参数怎么调：幅度、速度、Zoom、接缝

### 6.1 全局幅度范围

在 `config/pipeline.yaml`：

```yaml
pan_amplitude_deg: [38.0, 72.0]
tilt_amplitude_deg: [22.0, 44.0]
roll_amplitude_deg: [12.0, 28.0]
zoom_amplitude_deg: [6.0, 13.0]
```

想让 pan 更大，可以改成 `[50, 85]`，然后重新运行 `plan`。不要只改 CASE_PLAN 后忘记保存，因为再次运行 plan 会覆盖它。

### 6.2 全局速度范围

```yaml
speed_multiplier_range: [1.05, 1.40]
sequential_motion_fraction: 0.78
```

- `speed_multiplier` 越大，单个动作越快；建议 0.7～2.0，超过 2 容易显得突兀。
- `sequential_motion_fraction` 越小，顺序动作越早完成；建议 0.5～1.0。
- 叠加动作的速度倍率越大，时间脉冲越窄，但所有动作仍在镜头中段重叠。

### 6.3 单独改某个 case

在 `output/CASE_PLAN.json` 找到对应 case 的 `actions`：

```json
{
  "type": "pan_left",
  "amplitude_deg": 58.0,
  "speed_multiplier": 1.25,
  "phase": 0.42
}
```

- 改 `amplitude_deg` 调幅度；
- 改 `speed_multiplier` 调速度；
- 改 `phase` 调叠加动作起止错位；
- 顺序和叠加是同一个 recipe，想保持配方对应，两个 case 要改成一致。

修改后只重渲染这两条：

```bash
local/.venv/bin/python scripts/pipeline.py render --case recipe_01_seq --overwrite
local/.venv/bin/python scripts/pipeline.py render --case recipe_01_sim --overwrite
```

### 6.4 Zoom 为什么不要再加太大

Zoom 是改变 HFOV，不是 dolly。V2 已把幅度限制到 6°～13°，并有 36°～108°硬边界。若确实要加大：

1. 每次只增加 2°～3°；
2. 先渲染 1 个 case；
3. 检查边缘是否严重拉伸、方向是否产生倒置错觉；
4. 不要把 `hard_hfov_max_deg` 提到 150°以上；普通 rectilinear 视角不适合极端广角。

### 6.5 接缝安全参数

```yaml
hard_yaw_center_abs_deg: 90
seam_margin_deg: 25
```

- 增大 `seam_margin_deg`：更保守、更不容易看到接缝，但可用 pan 幅度变小；
- 减小它：可扫更远，但输入拼接误差更容易进入画面；
- 不建议小于 15°。

计划阶段会把超界轨迹按比例缩小并把实际 scale 写入 `axis_scales.seam`。如果经常小于 0.7，说明你的幅度设置过激，应回调 pan/roll/HFOV。

## 7. 第三步：先做冒烟渲染

不要一上来跑 100 条。先做 2 条相同 recipe 的顺序/叠加版本：

```bash
local/.venv/bin/python scripts/pipeline.py render --limit 2
```

检查：

- `site/media/cases/recipe_01_seq/ref.mp4`
- `site/media/cases/recipe_01_seq/target.mp4`
- `site/media/cases/recipe_01_sim/ref.mp4`
- `site/media/cases/recipe_01_sim/target.mp4`

应确认：

1. 左右都存在；
2. 都是 15 秒；
3. 左右同一时刻运动方向一致；
4. 没有触及左右接缝；
5. Zoom 没有翻转或严重拉伸；
6. 清晰度满足要求。

## 8. 第四步：全量渲染

```bash
local/.venv/bin/python scripts/pipeline.py render --workers 2
```

参数说明：

- `--workers 1`：最稳、占用较低；
- `--workers 2`：推荐，同时处理 2 个 case；
- `--workers 3/4`：会同时解码多路 5K 并开启更多 ffmpeg，未必更快；
- `--overwrite`：覆盖已存在的完整 case；
- `--limit N`：只跑前 N 个；
- `--case ID`：只跑指定 case，可以重复使用。

中断后重新运行会跳过已完整存在的 case。写入过程中使用 `.part.mp4`，只有 ffmpeg 成功退出才原子改名为正式 MP4。

如果你修改过 CASE_PLAN，必须使用 `--overwrite` 重渲染对应 case。

- 每对 ref/target 分辨率相同；
- 每条像素数 ≤921,600；


TOS 发布只上传 `site/`：

- `index.html`；

不要上传 `local/.venv` 或 39GB 原始数据集。项目名使用 `motion`。上传后需要从外网实际打开入口，并随机点至少 3 个横屏、3 个竖屏和 2 个特殊投影 case，确认 MP4 Range 请求和 MIME 类型正常。

## 13. 常见问题

### 页面只有左边或右边

检查 `site/index.html` 是否由当前 `build_site.py` 重建。V2 的 `.video-pair` 固定为两列，默认不会隐藏。还要确认该 case 的 `ref.mp4` 和 `target.mp4` 都存在。

### 视频不是 15 秒

不要靠播放器显示猜。运行 `validate`；它用帧数/fps 检查。正确结果是 300/20=15 秒。

### 竖屏看起来太广

程序会按 95°垂直 FOV 自动降低基础 HFOV。想更窄可把 `max_vertical_fov_deg` 从 95 改成 85，然后重新 plan/render。

### 画面出现接缝

先看 metadata 中 `max_abs_sampled_longitude_deg`。如果普通组合低于 155°仍有缝，说明缝不是 ERP 左右边界，而可能是相机内部镜头拼接线；应换源或改初始观察方位。小行星/兔子洞使用完整 360°，不能保证完全排除接缝。

### 运行很慢

- 保持 `workers=2`；
- 原始素材放 SSD；
- 先 `--limit 2`；
- 不要把输出改成 4K；
- 不要把 fps 从 20 随意提到 60。

### 想继续扩充数量

先增加 `combo_recipe_count`，然后同步增加 sequential/simultaneous，使两者相等；总数验证目前固定要求 100。如果要改变交付规模，需要同时修改配置检查、验证期望和文档，不能只改一个数字。
