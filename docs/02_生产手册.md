## 3. 准备原始素材

本机默认路径已经写在 `config/pipeline.yaml`：

```yaml
source_roots:
  360x: ../panocam/data/dataset_showcase/360x/hr_samples
  commons: local/sources/commons
```

相对路径以新项目根目录为基准。360+x 体积约 39GB，因此只读引用相邻旧素材目录；本次新增的 Commons/NASA 文件位于当前项目 `local/sources/commons`。两处都不读取旧代码或旧 demo。

如果换电脑，不必改代码。可以直接覆盖：

```bash
local/.venv/bin/python scripts/pipeline.py audit \
  --source-root-360x /data/360x/hr_samples \
  --source-root-commons /data/wikimedia
```

渲染时要传入同样的覆盖目录，或把它们永久写回 `config/pipeline.yaml`：

```bash
local/.venv/bin/python scripts/pipeline.py render --workers 2 \
  --source-root-360x /data/360x/hr_samples \
  --source-root-commons /data/wikimedia
```

要增加源视频，在 `config/pipeline.yaml` 的 `sources:` 下增加：

```yaml
- dataset: 360x
  file: your_file.mp4
  manual_decision: pass
  allowed_sides: [ref]
  privacy_face_blurred: true
  note: 固定机位，人物持续运动；人脸已按数据集官方流程模糊
```

`manual_decision: pass` 不是无条件放行；它仍需通过分辨率、帧率、全局运动和切镜阈值。静止场景可增加 `allow_static_scene: true`，但相机稳定阈值不会放宽。`allowed_sides` 控制 REF/TARGET 角色；360+x 因官方人脸模糊统一设为 `[ref]`。

## 4. 第一步：筛选素材

```bash
local/.venv/bin/python scripts/pipeline.py audit
```

它会：

1. 检查文件存在和能否解码；
2. 检查 ≥3600×1800、≥20 fps、≥16 秒；
3. 在整段视频中均匀取最多 8 个完整 15 秒窗口；
4. 对每个窗口计算 `dynamic_score`；
5. 计算 `dynamic_score_max`，剔除剪辑切镜或全屏转场；
6. 计算 `global_flow_px` 和 `coherent_shift_px`；
7. 联合人工决定给出最终 pass/reject；
8. 写入 `output/SOURCE_AUDIT.json`。

建议检查：

```bash
python3 - <<'PY'
import json
d=json.load(open('output/SOURCE_AUDIT.json'))
print(d['summary'])
for s in d['sources']:
    print(s['final_status'], len(s['usable_windows']), s['file'])
PY
```

### 筛选参数怎么调

| 参数 | 默认 | 调大以后 | 调小以后 |
| --- | ---: | --- | --- |
| `dynamic_score_min` | 0.006 | 更严格，剔除更多弱动态 | 保留更多轻微动态 |
| `scene_cut_dynamic_ratio_max` | 0.42 | 容许更强全屏变化 | 更严格剔除剪辑切镜 |
| `global_flow_px_max` | 1.8 | 容许更多全局运动 | 更严格剔除运动机位 |
| `coherent_shift_px_max` | 10 | 容许更大整体位移 | 更严格剔除统一摇移 |
| `max_windows_per_source` | 8 | 检查更全面、减少复用但更慢 | 更快但覆盖时间段更少 |
| `min_width/min_height` | 3600/1800 | 只留更高分辨率 | 可接受更低清晰度 |
| `min_fps` | 20 | 只留更流畅源 | 允许低帧率源 |

不要仅靠调宽阈值让运动相机通过。对算法不确定的源，应先目视检查，再用 `manual_decision` 明确记录。

## 6. 参数怎么调：幅度、速度、Zoom、接缝

### 6.1 全局可调参数总表

所有常调默认值都在 `config/pipeline.yaml`，不需要改 Python：

| 参数 | 当前默认 | 含义与调节影响 |
| --- | ---: | --- |
| `pan_amplitude_deg` | 72°～155° | 左右摇基础幅度；调大更远，但更容易触发接缝安全缩放 |
| `tilt_amplitude_deg` | 42°～92° | 上下摇基础幅度；调大更激烈，极端竖屏要检查画面边缘 |
| `roll_amplitude_deg` | 95°～420° | 普通顺/逆时针滚转幅度 |
| `spin_360_amplitude_deg` | 360°～720° | 360°环绕 showcase 的滚转总量 |
| `zoom_amplitude_deg` | 4°～10° | 普通组合的 HFOV 改变量，刻意维持小幅 |
| `hard_yaw_center_abs_deg` | 112° | yaw 中心硬上限；最终仍需接缝射线检查 |
| `hard_pitch_abs_deg` | 72° | pitch 绝对上限 |
| `hard_roll_abs_deg` | 720° | roll 绝对上限，允许两圈滚转 |
| `hard_hfov_min/max_deg` | 36°/108° | Zoom 后 HFOV 硬边界 |
| `backbone_start/end_seconds` | 0/15 | 持续动作覆盖范围；不要缩短，否则可能出现停顿 |
| `short_duration_seconds` | 0.55～2.20s | 快动作候选时长 |
| `medium_duration_seconds` | 2.20～6.50s | 中等时长动作 |
| `long_duration_seconds` | 6.50～13.50s | 长动作，用于不规则叠加 |
| `fast_action_probability` | 0.72 | 动作走快速分布的概率；这是人工加入的速度 bias |
| `medium_action_probability` | 0.20 | 动作走中速分布的概率；剩余概率走长动作 |
| `speed_multiplier_range` | 0.75～3.60 | 全速度倍率范围 |
| `fast_speed_multiplier_range` | 1.80～3.60 | 快速动作专用倍率范围 |
| `whip_probability` | 0.34 | 普通配方额外变成甩镜的概率；确定性规则还会保证最低覆盖 |
| `large_whip_probability` | 0.18 | 甩镜升级为大范围甩镜的概率 |
| `spin_360_probability` | 0.20 | 有 roll 动作时升级为 360°滚转的概率 |
| `whip_duration_seconds` | 0.50～1.45s | 甩镜完成大幅旋转所用时间 |
| `whip_pan_amplitude_deg` | 85°～165° | 左右甩镜原始幅度 |
| `whip_tilt_amplitude_deg` | 60°～115° | 上下甩镜原始幅度 |
| `action_start_latest_seconds` | 12.5s | 非 backbone 动作允许的最晚开始时间 |
| `min_start_separation_seconds` | 0.35s | 不同动作开始时间的最小优先间隔 |
| `stationary_speed_threshold_deg_per_second` | 0.50°/s | 低于此合成速度的帧视为停顿 |
| `max_stationary_run_frames` | 1 | 最长允许连续停顿帧；当前只容许数值误差级 1 帧 |
| `seam_margin_deg` | 18° | ERP 左右边缘安全余量，越大越保守 |
| `special_roll_total_deg` | 220°～540° | 小行星/兔子洞持续滚转总量 |
| `special_zoom_percent` | 2.5%～7% | 特殊投影 scale 的轻微呼吸幅度 |
| `special_zoom_cycles` | 1.0～2.5 | 15 秒内呼吸 Zoom 的循环次数 |

### 6.2 单个动作实例参数表

`CASE_PLAN.json` 每个普通动作都包含：

| 字段 | 含义 | 怎么调 |
| --- | --- | --- |
| `type` | pan/tilt/roll/zoom 方向 | 更改后必须仍属于 8 种 A 类白名单 |
| `axis` | yaw/pitch/roll/zoom | 由 type 决定，不建议手改 |
| `amplitude_deg` | 总幅度 | 调大范围更大；Zoom 仍建议 ≤10° |
| `start_seconds` | 动作开始时刻 | 调节错峰关系；范围 0～15 |
| `end_seconds` | 动作结束时刻 | 必须大于 start 且 ≤15 |
| `duration_seconds` | 动作持续时间 | 等于 end-start；同样幅度下越短越快 |
| `speed_multiplier` | 速度偏置倍率 | 计划阶段影响 duration，whip 中还控制中段陡峭度 |
| `speed_bucket` | `fast` 或 `varied` | 记录该动作来自哪个速度分布 |
| `window_bucket` | short/medium/long/whip/backbone | 记录时长分布来源 |
| `profile` | 逐帧速度曲线 | `linear/smooth/whip/swing/overshoot/pulse` |
| `curve_strength` | swing/overshoot 的回摆强度 | 调大更不规则，也更可能短暂反向 |
| `oscillation_cycles` | swing 变速次数 | 调大后 15 秒内加减速更频繁 |
| `nominal_speed_deg_per_second` | 名义平均速度 | 便于筛选，不直接参与渲染计算 |
| `is_backbone` | 是否覆盖完整 15 秒 | 每条必须恰好一个 true，且 start/end 为 0/15 |

速度曲线含义：

- `linear`：持续匀速，最适合 backbone；
- `smooth`：平滑加速和减速；
- `whip`：窗口中段集中完成动作，产生高速甩镜；
- `swing`：前进中叠加多次变速/反向；
- `overshoot`：越过目标后回摆；
- `pulse`：运动后返回原位。

### 6.3 单独改某个 case

示例：

```json
{
  "type": "pan_left",
  "amplitude_deg": 135.0,
  "start_seconds": 4.2,
  "end_seconds": 5.3,
  "duration_seconds": 1.1,
  "speed_multiplier": 3.2,
  "profile": "whip",
  "curve_strength": 0.0,
  "oscillation_cycles": 1.0,
  "is_backbone": false
}
```

修改 `start/end` 时同步修改 `duration_seconds`；修改后只重渲染该条：

```bash
local/.venv/bin/python scripts/pipeline.py render --case recipe_01_a --overwrite
```

然后必须重新运行 `validate`，因为验证器会检查真实合成速度，而不是相信手写的名义速度。

### 6.4 Zoom 为什么仍保持小幅

Zoom 是改变 HFOV，不是 dolly。普通组合限制为 4°～10°，并有 36°～108°硬边界。特殊投影 Zoom 使用 scale 的 ±2.5%～±7%。若要增加，建议一次只加 1°～2°或 1%，先渲染一个 case 检查边缘拉伸和倒置错觉。

### 6.5 接缝安全参数

```yaml
hard_yaw_center_abs_deg: 112
seam_margin_deg: 18
```

计划阶段用 5×5 视场射线检查每 4 帧的真实源经度。超界时只等比缩小 yaw/pitch，并把实际倍率写入 `axis_scales.seam_yaw_pitch`。Roll 绕光轴转动，不把视角中心推向 ERP 接缝，因此 360°滚转不会被这个倍率缩小。小行星/兔子洞使用完整 360°，只能调整接缝方向，不能彻底排除原素材接缝。

1. 左右都存在；

3. 左右同一时刻运动方向一致；

5. 甩镜够快、滚转幅度够大，但没有触及左右接缝；
6. Zoom 没有翻转或严重拉伸；
7. 清晰度满足要求。

## 8. 第四步：全量渲染

```bash
local/.venv/bin/python scripts/pipeline.py render --workers 2
```

参数说明：

- `--workers 1`：最稳、占用较低；
- `--workers 2`：推荐，同时处理 2 个 case；
- `--workers 3/4`：会同时解码多路 5K 并开启更多 ffmpeg，未必更快；
- `--overwrite`：覆盖已存在的完整 case；
- `--limit N`：只跑前 N 个；
- `--case ID`：只跑指定 case，可以重复使用。

中断后重新运行会跳过已完整存在的 case。写入过程中使用 `.part.mp4`，只有 ffmpeg 成功退出才原子改名为正式 MP4。

如果你修改过 CASE_PLAN，必须使用 `--overwrite` 重渲染对应 case。

## 13. 常见问题

### 页面只有左边或右边

检查 `site/index.html` 是否由当前 `build_site.py` 重建。V2 的 `.video-pair` 固定为两列，默认不会隐藏。还要确认该 case 的 `ref.mp4` 和 `target.mp4` 都存在。

### 视频不是 15 秒

不要靠播放器显示猜。运行 `validate`；它用帧数/fps 检查。正确结果是 300/20=15 秒。

### 竖屏看起来太广

程序会按 95°垂直 FOV 自动降低基础 HFOV。想更窄可把 `max_vertical_fov_deg` 从 95 改成 85，然后重新 plan/render。

### 画面出现接缝

先看 metadata 中 `max_abs_sampled_longitude_deg`。如果普通组合低于 162°仍有缝，说明缝不是 ERP 左右边界，而可能是相机内部镜头拼接线；应换源或改初始观察方位。小行星/兔子洞使用完整 360°，不能保证完全排除接缝。

### 运行很慢

- 保持 `workers=2`；
- 原始素材放 SSD；
- 先 `--limit 2`；
- 不要把输出改成 4K；
- 不要把 fps 从 20 随意提到 60。

### 想继续扩充数量

先增加 `combo_recipe_count`，然后同步增加 `hybrid_a_cases` / `hybrid_b_cases`，使两者相等；总数验证目前固定要求 100。如果要改变交付规模，需要同时修改配置检查、验证期望和文档，不能只改一个数字。
